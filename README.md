# 내 일본어 카드

[EternalOlive/memory-cards-web](https://github.com/EternalOlive/memory-cards-web)의 개인용 포크입니다. 원본 사이트와 다른 사용자의 저장소는 변경하지 않습니다.

## 사용

본인 GitHub Pages 주소에서 GitHub 연동을 열고 기존 학습 데이터가 들어 있는 Gist를 연결합니다. 각 브라우저에서 한 번씩 연결해야 합니다. 공개 사이트 저장소에는 개인 카드, 학습 기록, Gist 식별자, 토큰을 넣지 않습니다. GitHub의 secret Gist는 주소를 아는 사람이 읽을 수 있는 비목록 데이터입니다.

Obsidian Memory Cards Sync 2.1.3은 노트를 텍스트와 강조 범위로 보냅니다. 앞면 예문은 노란색/회색 링크 강조와 줄바꿈을 유지하고, 뒷면 번역 예문도 강조를 유지합니다. 글자 선택과 복사가 가능합니다.

기존 카드 ID, 학습 기록과 복습 예정일을 보존합니다. 새 답변부터 Anki 방식의 SM-2를 적용합니다. 전환 후 모든 기기에서 개인용 주소를 사용합니다. 원본 사이트는 새 학습 기록 형식을 읽지 못합니다.

## 동기화 구조

- Obsidian 노트 파일은 Syncthing으로 전달합니다. 원문 변경은 기존 기기별 원문 변경 기록을 사용합니다.
- 각 브라우저의 답변은 먼저 로컬 전송 대기열에 저장하고, 그 브라우저의 Gist 기록 파일에 추가합니다. 다른 기기의 파일을 덮어쓰지 않습니다.
- 응답이 끊겨도 동일한 변경 ID로 재확인하여 중복 답변을 피합니다.
- 카드와 덱의 삭제 기록은 계속 유지하여 오래된 데이터가 돌아와도 재등록하지 않습니다. 기본 덱도 덱 메뉴에서 삭제할 수 있습니다. 하위 덱과 소속 카드는 기존 확인창에 표시된 범위대로 함께 삭제되며, 삭제 전 학습 기록은 보존됩니다.
- 동일 카드에 여러 기기가 답변하면 답변 기록은 모두 보존합니다. 현재 복습 상태는 변경 순서상 마지막 답변의 상태를 사용하며 동시 답변을 재계산하지는 않습니다.
- 같은 브라우저의 여러 탭은 Web Locks로 전송을 직렬화합니다. 최신 Chrome/Edge 및 Android Chrome을 사용합니다.
- 세션 설정은 브라우저별입니다. 웹사이트 자체를 오프라인에서 새로 여는 기능은 보장하지 않습니다. 열린 페이지의 미전송 답변은 재연결 때 전송합니다.

## 구현

- sien-render.js: 텍스트 및 허용한 강조/링크만 DOM으로 표시합니다.
- sien-study.js: 변경 기록 병합, 삭제 보호, 재전송 중복 제거를 담당합니다.
- sien-app.js: 기기별 Gist 전송, 로컬 전송 대기열, 기존 화면 연결을 담당합니다.
- sien.css: 카드 텍스트의 줄바꿈과 강조 색상입니다.

스터디 현황은 원본과 같은 Study Companion 서버에 로그인하여 확인합니다. 개인 카드와 복습 데이터 저장은 GitHub Gist가 담당합니다.

## 검사

node --test queue.test.cjs sm2.test.cjs study.test.cjs network.test.cjs로 출제 순서·일정·병합·네트워크 정책을 검사합니다. 브라우저 검사에는 격리된 합성 카드와 모의 Gist를 사용하여 채점, 재시작, 두 기기 병합, 삭제, 네트워크 오류와 재시도를 확인합니다. 실제 Android 기기 테스트는 별도 확인이 필요합니다.

학습 화면은 Space/Enter로 답을 보고 1~4 또는 Z/X/C/V로 채점합니다. 버튼에 다음 복습 간격을 표시하고 출처·품사·JLPT는 작은 속성 영역에 표시합니다. GitHub 동기화는 접속과 화면 복귀, 답변 및 편집을 계기로 예약합니다. 짧은 간격의 변경은 아래 요청 조절 정책에 따라 묶습니다. 종료 시에는 전송 대기 기록을 keepalive 요청으로 보내고, 강제 종료나 오프라인으로 완료하지 못한 기록은 다음 접속에서 같은 ID로 재전송합니다.

## 개인 학습 설정 (2026-10-16)

- 발음, 각 뜻, 예문, 작은 출처 영역으로 뒷면을 구분합니다. v1 내보내기의 첫 문단 필드 구분자를 화면에서만 줄바꿈하며 카드 본문과 강조 위치는 변경하지 않습니다.
- 키보드 설정은 입력 배치에서 변경합니다. 중복 키를 거부하고 기본값으로 복원할 수 있습니다. 컨트롤러 설정과 폴링은 제거했습니다.
- SM-2 신규 단계는 1분/10분, 졸업 1일, 쉬움 4일입니다. 재학습은 10분이며 복습 간격·카드별 ease·지연·상한·fuzz를 반영합니다. 가져온 Anki 로그의 factor 또는 최초 이관 시 보관한 base의 원본 계수를 ease 초기값으로 사용하며 이후 SM-2 상태에 보존합니다. 현재 FSRS difficulty를 원본 계수로 취급하지 않습니다. 원본 계수가 없는 신규 카드는 2.5를 사용합니다.
- 기존 학습 기록을 일괄 재생하거나 만기를 재설정하지 않습니다. 저장된 `fsrs` 키는 기존 동기화/암기상태 연결을 위한 호환 형식이며, 새 일정은 `sien-sm2.js`가 계산합니다. `sm2` 필드와 답변 로그에 결과를 함께 보관합니다.
- 기존 저장 세션, 오답 복습, 상세 선택에도 같은 복습 예정일을 적용합니다. 미래의 복습 카드는 제외합니다. 신규·복습이 남아 있는 동안 짧은 학습 단계는 예정 시각을 지키며, 모두 끝나면 아래의 Anki 20분 미리 학습 정책을 적용합니다. 다른 기기의 답변이 동기화되어 현재 카드의 일정이 미래로 바뀌면 즉시 다음 카드로 넘어가며, 답변 직전에도 예정일을 재검사합니다.
- Anki의 [SM-2 설명](https://faqs.ankiweb.net/what-spaced-repetition-algorithm.html)과 [학습 단계](https://docs.ankiweb.net/deck-options.html#learning-steps)를 참고합니다. 웹의 분산 시드는 별도 구현이므로 Anki 프로그램과 무작위 간격이 항상 일치한다는 뜻은 아닙니다.
- 찌르기는 활성 창에서 5초마다 확인하며 별도 팝업에 보관합니다. 확인 전까지 다른 안내가 덮지 않습니다. 서버는 같은 계정의 첫 수신 기기에 전달하므로 다른 사이트/Anki가 먼저 받은 알림을 이 사이트가 다시 가져올 수는 없습니다. 사이트가 닫힌 상태의 운영체제 푸시 알림은 지원하지 않습니다.

격리된 브라우저에서 신규/재학습 단계, 재접속, 진행 중 답변 되돌리기, 사용자 키 변경, 알림 수신을 검증합니다. 실제 사람에게 찌르기를 보내는 검사는 하지 않습니다.

팁과 설명은 Obsidian의 제목·문단·목록·중첩 콜아웃을 유지합니다. 접기 표식은 details/summary로 표시하며 마우스·터치·Enter/Space로 펼칩니다. 설명을 펼치거나 읽는 동작은 카드 뒤집기/채점과 분리했습니다. 플러그인 2.1.2의 서식 갱신 후 적용되며 기존 카드 ID와 학습 기록을 유지합니다.

## 모바일 연결 및 덱 화면 (2026-10-17)

- HTTP 409 충돌, 일시적인 연결 실패와 서버 오류는 원격 기록을 다시 읽고 같은 변경 ID로 자동 재시도합니다. 재시도 간격은 2초부터 점차 늘리고 기기별로 약간 분산합니다. GitHub 요청 제한은 서버의 대기 시간을 우선합니다.
- 원격에서 전송한 변경 ID를 확인한 뒤에만 대기 기록을 지웁니다. 성공 시 해당 동기화 실패 안내도 지웁니다. 인증/데이터 오류는 바로 표시하고, 반복되는 통신 실패는 안내를 유지합니다.
- 설정의 GitHub 연동에 최근 30건의 기기별 오류/복구 내역과 복사 버튼이 있습니다. 단계, HTTP 번호, 시각, 소요 시간, 대기 건수만 저장하며 토큰·주소·카드 본문은 포함하지 않습니다.
- 모바일 덱 목록은 제목/버튼/카드 수를 분리합니다. 긴 덱 이름을 줄바꿈하고 신규·학습·복습을 각 숫자에 표시합니다. 기존 덱 작업은 그대로 사용할 수 있습니다.

## 2026-10-17 학습 패널
오른쪽 메뉴에서 카드 정보와 스터디를 전환합니다. 카드 탭에는 현재 복습 일정·풀이 횟수와 기존 메모/조작이 표시됩니다. 스터디 탭은 기존 멤버들의 공부 현황을 모바일에서도 표시하며, 로그인 전에는 계정 연결 안내를 제공합니다.

Obsidian 내장 모드에서는 동일한 사이트를 별도 origin의 iframe으로 표시합니다. 외부 팝업과 링크 이동을 막고 기존 GitHub 연결/스터디 로그인 양식을 사용합니다. 플러그인과 사이트 간 메시지는 화면 준비 여부, 카드 ID에 따른 원본 편집 요청과 복귀 상태를 전달합니다. 토큰이나 노트 본문은 전달하지 않습니다.


## 2026-10-17 원본 노트 편집 (20261017-12)
플러그인 2.1.7의 내장 학습 화면에서 카드의 단어 또는 원본 편집을 누르면 현재 기기의 Obsidian 노트가 열립니다. PC는 별도 노트 탭, 모바일은 학습 복귀 버튼이 있는 편집 탭을 사용하며 플랫폼은 Obsidian이 판별합니다. 편집 중 학습 시간을 멈추고 돌아오면 같은 카드와 정답 공개 상태를 유지합니다. 게시된 원본 변경을 다시 받아 현재 카드 표시만 갱신합니다. 단어 클릭·Enter/Space는 채점으로 전파하지 않습니다. 일반 브라우저나 이전 플러그인은 원본 편집 버튼을 표시하지 않습니다.

## 2026-10-17 일본어 예문 자동 줄바꿈 (20261017-13)
일본어 앞면은 단어 중간 줄바꿈을 막던 공통 keep-all 규칙에서 분리합니다. 화면 폭에 맞춰 일본어를 자연스럽게 접고 문장부호 금칙을 적용합니다. 원문의 명시적인 줄바꿈, 예문 사이 구분, 강조 범위와 한국어 뒷면의 줄바꿈 규칙은 유지합니다. 표시만 변경하므로 플러그인 재설치나 카드 재등록은 필요하지 않습니다.

## 2026-10-17 전송 중 앱 종료와 요청 제한 (20261017-14)
진행 중인 저장과 종료 전송이 겹치지 않도록 같은 Web Lock을 사용합니다. 이미 저장 중이거나 다른 탭이 저장 중이면 종료 요청을 중복 발송하지 않고 미확인 답변을 로컬 대기열에 유지합니다. 각 답변은 즉시 기기에 보관하고 동기화 대기열에 넣습니다. 서버가 지정한 대기 시간은 화면 재접속과 수동 재시도에도 지키며, 남은 분과 재시도 시각·미전송 건수를 표시합니다. 오류 내역에는 한도·잔여량·해제 시각 등 숫자와 분류만 추가합니다. 토큰·카드 본문·원격 주소는 기록하지 않습니다.


## 2026-10-17 중복 요청과 전송 빈도 조절 (20261017-15)

- 답변은 즉시 로컬 대기열에 저장합니다. GitHub 쓰기는 최소 10초 간격으로 묶고, 다른 기기가 방금 저장했으면 해당 시각을 기준으로 잠시 양보합니다. 제한이나 다른 기기의 저장이 없으면 예약된 변경을 자동 전송합니다.
- 수동/자동 동기화가 겹치면 실행 중인 작업에 합류합니다. 탭 저장 잠금을 얻은 뒤에도 공유 제한 시각을 다시 확인합니다. 종료 전송과 새로고침도 같은 제한과 전송 간격을 지킵니다.
- 변경 조회는 ETag/304를 사용합니다. 정상 PATCH 응답에서 전송 ID를 확인하여 완료 확인용 GET 하나를 줄입니다. 불확실한 전송은 다음 조회에서 같은 ID로 복구합니다.
- 제한이 반복되면 대기를 늘리고 GitHub가 지정한 더 긴 제한을 우선합니다. 네트워크나 GitHub 제한 자체를 없애는 기능은 아닙니다.
- 검증: 네트워크 단위 13개, 학습/병합 단위 23개, 브라우저 회귀 21개와 요청량 시나리오 7개 통과. 빠른 답변 5개의 전송 1회 묶기, 대기 중 탭 차단, 종료/재접속과 제한 해제 후 기록 복구를 모의 API로 검사했습니다. 실제 Android 통신은 별도 확인이 필요합니다.


## 2026-10-17 사이트 동기화 감사 (20261017-16)

- 원격에서 현재 카드의 내용이 바뀌면 학습 위치·정답 공개 여부·응답 시간을 유지하며 앞뒷면 표시를 갱신합니다. 사라진 서식 속성도 큐에 남기지 않습니다.
- 다른 기기의 최근 쓰기에 양보할 때에도 이미 받은 원격 내용은 표시합니다. 미전송 답변은 로컬 대기열에 유지하며 서버에서 확인한 뒤에만 지웁니다. 서버가 지정한 요청 제한은 계속 준수합니다.
